# Deploy to Render

## Quick start

1. Push this repo to GitHub/GitLab/Bitbucket.
2. Go to [Render Dashboard](https://dashboard.render.com/) → **New** → **Blueprint**.
3. Connect your repo and select the branch.
4. If your repo root is `freelancing/` (parent of `product_reasearch/`), set **Root Directory** to `product_reasearch`.
5. Click **Apply**.

## Environment variables

Add these in **Render Dashboard → Your Service → Environment**:

| Variable | Required | Notes |
|----------|----------|-------|
| `DATABASE_URL` or `SUPABASE_DB_URL` | Yes | PostgreSQL connection string (you already have Supabase) |
| `DJANGO_SECRET_KEY` | Yes | Auto-generated by blueprint, or set your own |
| `OPENAI_API_KEY` | If using | From your .env |
| `GEMINI_API_KEY` | If using | From your .env |
| `APIFY_API_TOKEN` | If using | From your .env |
| `AWS_ACCESS_KEY_ID` | If using S3 | Supabase storage |
| `AWS_SECRET_ACCESS_KEY` | If using S3 | Supabase storage |
| `AWS_STORAGE_BUCKET_NAME` | If using S3 | e.g. `videos` |
| `AWS_S3_ENDPOINT_URL` | If using S3 | Supabase S3 endpoint |

## Celery + Redis

The blueprint includes:
- **Free Redis** (Key Value) — Celery broker and result backend
- **Celery worker** — processes background tasks (starter plan, ~$7/mo)

Add `DATABASE_URL` or `SUPABASE_DB_URL` to the worker's environment (same as the web service) so tasks can access the database.

## Create admin user

After deploy, open **Shell** in Render Dashboard and run:

```bash
cd api && python manage.py createsuperuser
```
